# FB → YouTube Uploader Pro

أداة مكتبية مكتوبة بـPython لإدارة مراجعة مقاطع Facebook ونشرها على YouTube، مع فحص مسبق، ومتابعة سجلّ الحقوق، وإعادة المحاولة. إصدار التطبيق الحالي: **4.48.0**.

سجل الإصدارات: `CHANGELOG.md`.

### إصلاحات 4.48.0

- عزل كل تنزيل في مجلد staging فريد؛ لا تُحذف ملفات المستخدم القديمة، وتُستخدم أسماء ملفات فريدة.
- اشتراط نجاح `ffprobe` والتحقق من تدفق الفيديو والحجم والمدة والحاوية قبل الرفع؛ فشل الفحص يبقى فشلاً مع سبب وإجراء.
- حفظ إيصال YouTube محلياً قبل تنظيف قائمة الانتظار؛ نتيجة الرفع غير المؤكدة تتطلب مطابقة يدوية ولا تُعاد تلقائياً.
- حفظ الإعدادات وملفات الحالة ذرياً مع نسخ احتياطية واستعادة آمنة، ورفض متابعة التشغيل عند تلف سجل حرج بلا نسخة صالحة.
- إضافة تبويب إعدادات محلي للمجلدات ومسار OAuth؛ حقول الأسرار مخفية، والسجلات تُنقّح من الرموز وكلمات المرور.
- إزالة خصائص إخفاء أتمتة Chrome، وإيقاف العمل عند login أو CAPTCHA أو checkpoint بدلاً من تجاوزها.
- تطبيع الروابط والتحقق من Facebook/YouTube، وإيقاف النتائج غير المعروفة بدلاً من تسجيلها كنجاح.
- استخدام `tzdata` لتوقيت Pacific دقيق على Windows وLinux.
- لم تُجرَ عمليات رفع حقيقية أثناء الاختبار. راجع `FINAL_VALIDATION_4.48.0.md` لنتائج التحقق وحدوده.

### إصلاحات 4.47.0

- إعادة التفويض إلى YouTube عند انتهاء التوكن حتى إن لم يحتوِ على `refresh_token`، مع إبقاء وضع CLI غير التفاعلي آمناً.
- حفظ معرّف الفيديو في رابط المصدر، توحيد روابط `sk=about` إلى تبويب Reels، وقبول صيغ Facebook `/share/r/` و`/share/v/` لتمريرها إلى محلّل الروابط.
- عند غياب FFmpeg يُختار ملف فيديو وصوت مدمجان مسبقاً بدلاً من محاولة دمج مسارات منفصلة.
- أخطاء دورات المراقبة تُسجّل في ملخص التشغيل والنتيجة البرمجية ولا تظهر كنجاح صامت.
- تصحيح دليل التشغيل: مراجعة `strict` اليدوية تتم من الواجهة الرسومية؛ CLI لا يعرض نافذة موافقة لكل فيديو.
- التحقق المحلي: **443 اختباراً ناجحاً**، ونجاح Ruff وتجميع Python. لم تُجرَ عملية رفع فعلية لحسابات Facebook أو YouTube أثناء هذه الاختبارات.

## المتطلبات

- Python 3.11 أو أحدث.
- Tkinter لتشغيل الواجهة الرسومية.
- ملف OAuth من Google باسم `client_secrets.json`، يوضع محلياً بجانب البرنامج.
- `ffprobe` من حزمة FFmpeg مطلوب للتحقق من سلامة كل ملف قبل الرفع؛ من دونه يُحظر الرفع.
- `ffmpeg` اختياري للتنزيل بصيغ مدمجة، لكنه مطلوب لمعالجة الفيديو والشعار والصورة المصغّرة.

## التثبيت والتشغيل

على Windows:

```bat
setup.bat
run_gui.bat
```

على Linux:

```bash
./setup.sh
./run_gui.sh
```

ينشئ التثبيت `config.ini` من `config.ini.example` عند عدم وجوده. أضف إعداد OAuth محلياً، ثم نفّذ فحص الجاهزية قبل التشغيل الآلي:

```bash
./run_automation.sh --preflight
```

## بوابة الحقوق الافتراضية

يبدأ الإعداد الجديد بوضع `strict` مع معاينة وموافقة يدوية قبل كل رفع. لا يملأ القالب إقراراً عاماً بامتلاك الحقوق، ولا يحوّل الإعدادات القديمة من `strict` إلى وضع رفع آلي. لا يُقبل الرفع إلا بعد مراجعة الفيديو وسجل حقوقه؛ ويمكن للمشغّل تفعيل `operator_confirmed` صراحةً فقط إذا كان الإقرار المكتوب صحيحاً وينطبق على المواد المحددة. يحتفظ التطبيق بأي قيمة صريحة موجودة في `config.ini` كما هي.

وضع `--cli` لا يستطيع عرض نافذة مراجعة؛ لذلك يعتمد على سجل حقوق صالح لكل فيديو أو على إقرار مشغّل صريح وصحيح. لا تفعّل الوضع الآلي لمواد لا تملك حق إعادة نشرها أو إذناً موثقاً لها.

للتشغيل الآلي استخدم `./run_automation.sh` أو `run_automation.bat` على Windows. وضع `--cli` لا يفتح نافذة مراجعة لكل فيديو؛ في وضع `strict` استخدم الواجهة الرسومية للموافقة اليدوية. لا تفعّل `operator_confirmed` إلا بإقرار صادق ينطبق على المواد التي تملك حق نشرها أو إذناً موثقاً لها.

## الاختبارات وفحص الشيفرة

```bash
./run_tests.sh
```

على Windows شغّل `run_tests.bat`. ولتشغيل الفحوص بعد تثبيت متطلبات التطوير:

```bash
python -m ruff check *.py tests/
python -m pytest -q
```

### تدقيق الاعتماديات

فحص الاعتماديات المثبتة من القفل الكامل:

```bash
.venv/bin/pip-audit -r requirements-lock.txt --no-deps --disable-pip
```

يتضمن `requirements-lock.txt` الاعتماديات المباشرة والانتقالية مثبتة؛ `--no-deps --disable-pip` يتجنب إنشاء بيئة مؤقتة عبر pip أثناء التدقيق.

## تنظيم المشروع

- `fb_youtube_uploader_v49_pro.py`: نقطة الدخول والواجهة والتدفق الرئيسي.
- ملفات Python الأخرى في الجذر: وحدات المصادقة، السلامة، المراجعة، التشخيص والتحكم.
- `tests/`: الاختبارات الحالية؛ `tests/fixtures/versions/` لقطات تاريخية تستخدمها اختبارات التوافق فقط.
- `docs/UPGRADE.md`: نقل الإعدادات والبيانات من تثبيت أقدم.
- `docs/FIRST_RUN.md`: دليل أول دورة رفع حية، خطوة بخطوة، مبنياً على نتائج فحص مُتحقَّق منها.
- `FINAL_VALIDATION_4.48.0.md`: نتائج الاختبارات والفحوص وحدود التحقق الحي للإصدار الحالي.
- `FINAL_VALIDATION_4.47.0.md`: تقرير تاريخي للإصدار السابق.
- `config.ini.example` و`rights_manifest.example.json`: قوالب آمنة للبدء.

## البيانات والأمان

لا ترفع `config.ini` أو ملفات OAuth والكوكيز أو مفاتيح AI أو سجلات التشغيل أو بيانات القنوات والفيديوهات. هذه الملفات مستثناة في `.gitignore`؛ لا تتجاوز الاستثناءات عند النشر. احتفظ بنسخة احتياطية محلية لبيانات التشغيل قبل أي ترقية.
