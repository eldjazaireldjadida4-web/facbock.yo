# دليل التشغيل الحي الأول — خطوة بخطوة

يساعدك هذا الدليل على تشغيل أول دورة حية بأمان. وضع `--cli` مخصص للتشغيل غير التفاعلي ولا يفتح نافذة موافقة لكل فيديو.

نفّذ الخطوات على **جهازك** — لا تُنقل كوكيز فيسبوك أو ملفات التفويض إلى أي جهاز آخر، ولا تشاركها.

## 1) التثبيت والفحص الأول

```bat
setup.bat
run_gui.bat
```
(على Linux: `./setup.sh` ثم `./run_gui.sh`)

عند أول تشغيل، ينشئ البرنامج `config.ini` من `config.ini.example`. لا تعِدّله بعد حتى تنتهي من قراءة هذا الدليل كاملاً.

## 2) الفحص المسبق (يجب أن ينجح قبل أي شيء آخر)

```bat
run_automation.bat --preflight
```
أو على Linux:
```bash
./run_automation.sh --preflight
```

يجب أن ترى `النتيجة: [OK]`. إذا ظهرت مشاكل تمنع التشغيل، عالجها قبل المتابعة. أبرزها:

- **Chrome غير موجود**: ثبّت Google Chrome (Selenium يجلب chromedriver تلقائياً).
- **ملف تفويض Google مفقود**: أنشئ OAuth client نوع Desktop في Google Cloud ونزّل `client_secrets.json` بجانب البرنامج.
- **أذونات config.ini**: نفّذ `chmod 600 config.ini` على Linux.

## 3) ربط قناة YouTube (مرة واحدة)

عند أول محاولة رفع سيفتح المتصفح لطلب إذن Google (ضغطة Allow). لا تشارك ملف التوكن الناتج `account1_token.json` مع أحد.

## 4) كوكيز فيسبوك (إذا كانت صفحاتك تتطلب تسجيل دخول)

صدّر ملف كوكيز من جلسة فيسبوك مسجّلة، وحدّد مساره من تبويب **Facebook** ثم فعّل استخدام الكوكيز واحفظ الإعدادات. الملف يحتوي بيانات جلسة خاصة — لا تشاركه ولا ترفعه لأي مكان.

## 5) أول دورة: محاكاة كاملة

قبل أي رفع حقيقي:

```bat
run_automation.bat --cli --dry-run --once
```
أو:
```bash
./run_automation.sh --cli --dry-run --once
```

يجب أن ترى في النهاية عدّ `محاكاة` بدل `مرفوع`. إذا فشل الفحص المسبق داخل الدورة ستظهر رسالة «أُوقف التشغيل قبل الرفع لأن فحص الجاهزية لم يجتز» — هذه سلوك سليم: عالج المشكلة المذكورة وأعد المحاولة.

## 6) أول دورة حية بمراجعة يدوية (بعد نجاح المحاكاة)

تأكد من الإعدادات التالية قبل البدء:

| الإعداد | القيمة | لماذا |
|---|---|---|
| `DRY_RUN` | `false` | للسماح بالرفع الفعلي |
| `RIGHTS_GATE_MODE` | `strict` | المراجعة اليدوية لكل فيديو |
| `REVIEW_BEFORE_UPLOAD` | `true` | توقف قبل كل رفع لمراجعة يدوية |

شغّل الواجهة الرسومية، وليس `--cli`، لأن المراجعة اليدوية تحتاج نافذة التطبيق:
```bat
run_gui.bat
```
أو:
```bash
./run_gui.sh
```

عند كل مقطع: راجع العنوان والوصف وسجل الحقوق في نافذة المراجعة قبل السماح بالرفع. لا ترفع شيئاً لا تملك حق نشره أو إذناً موثقاً له.

**مهم:** `REVIEW_BEFORE_UPLOAD=true` لا ينشئ نافذة مراجعة داخل `--cli`. التشغيل الآلي غير التفاعلي في وضع `strict` يتوقف قبل التنزيل. لا تستخدم `operator_confirmed` إلا إذا كان إقرار المشغّل صادقاً وينطبق على كل المواد، وأدخل مرجع الإثبات عند اختيار ترخيص/إذن/ملكية عامة.

## 7) التحقق بعد الدورة

راجع بالترتيب:
1. عدد `مرفوع` و`فاشل/مؤجل` في ملخص نهاية الدورة.
2. `errors.log` و`automation.log` في مجلد البرنامج — ابحث عن أي سطر يبدأ بـ `ERROR`.
3. قناة YouTube نفسها: العناوين والأوصاف صحيحة وغير مكررة.
4. `rights_manifest.json`: تسجيل المصدر والحق لكل مقطع مرفوع.

## 8) ما لا تفعله أبداً

- لا ترفع فيديو لم تراجعه بنفسك (البوابة `strict` موجودة لهذا السبب).
- لا تفعّل `ALLOW_PUBLIC_AUTO_PUBLISH` قبل عدة دورات حية ناجحة بمراجعة يدوية.
- لا تشارك `cookies.txt` أو `client_secrets.json` أو `account1_token.json`.
- لا تُشغّل البرنامج من مجلد عام بدون `chmod 600` لملفات الإعدادات والتوكن.

## 9) إن فشل شيء

- راجع `errors.log` أولاً — كل خطأ يُسجّل مع سياقه.
- أعد تشغيل `--preflight` لرؤية المشكلة المحدثة.
- إن توقفت الدورة بوجود قائمة انتظار، ستبقى العناصر المعلّقة محفوظة وتُستأنف بعد نجاح الفحص (بلا رفع مكرر).
- راجع `docs/UPGRADE.md` عند الترقية من تثبيت أقدم.
