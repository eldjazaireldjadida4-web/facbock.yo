# بحث مشاريع مفتوحة المصدر قابلة للدمج

**التاريخ:** 2026-11-09  
**المشروع:** FB → YouTube Uploader Pro

## المختار: faster-whisper

المستودع الرسمي `SYSTRAN/faster-whisper` يوفّر واجهة Python مباشرة، ترخيص MIT، وتشغيلاً محلياً على CPU بدقة `int8`؛ لذلك هو أسهل دمجاً من خدمة مستقلة أو برنامج كامل. أُضيف اختيارياً لتحويل كلام الفيديو إلى نص يثري وصف Gemini ووسومه، مع إبقاء عنوان Facebook كما هو. الإعداد مغلق افتراضياً؛ الصوت لا يغادر الجهاز، لكن النص المفرغ يصل إلى Gemini عند تفعيل الخيارين معاً. لا تُحمّل أوزان النموذج إلا عند أول استخدام.

## البدائل التي دُرست

- **whisper.cpp:** MIT ويدعم أنظمة متعددة مع اعتماديات تشغيل قليلة، لكنه يتطلب بناء CMake أو توزيع ملف تنفيذي وإدارة نموذج منفصل؛ واجهة CLI تحتاج WAV بصيغة PCM 16-bit. مناسب لاحقاً إذا صار حجم حزم Python عائقاً.
- **PySceneDetect:** BSD-3-Clause ومشروع نشط لكشف تغيّر المشاهد. يصلح مرحلةً لاحقة لاختيار مقاطع Shorts حسب المشاهد؛ المشروع الحالي يختار المقطع الأعلى صوتاً ويقصه عبر FFmpeg، وإضافة OpenCV الآن توسّع الحزمة بلا حاجة مباشرة.
- **videohash:** MIT لكشف المقاطع المتقاربة بصرياً؛ لكن `content_safety.py` ينفّذ بالفعل بصمة dHash لثمانية إطارات ومقارنة تقريبية. لا نضيف اعتماداً مكرراً قبل وجود حالة لا تغطيها البصمة الحالية، مثل تحمّل قصّ أو تدوير شديدين.
- **AutoClip:** مشروع MIT متكامل لتوليد المقاطع وإدارتها، لا مكتبة صغيرة؛ يضم تطبيقاً وخدمات وواجهات متداخلة مع وظائف هذا المشروع، لذا نأخذ منه أفكاراً فقط ولا ندمج شجرته كاملة.

## نطاق الدمج في 4.48.9

- تفريغ محلي اختياري بنماذج `tiny` و`base` و`small` على CPU.
- استخدام النص لتحسين الوصف والوسوم، من دون استبدال عنوان المصدر.
- حدّ للنص المرسل إلى Gemini، وكاش مبني على بصمة النص دون تخزين التفريغ الخام.
- الإيقاف يعيد المقطع إلى قائمة الانتظار؛ فشل التفريغ لا يمنع استخدام بيانات Facebook المتاحة.
- الاختبارات لا تنزّل نموذجاً ولا ترفع فيديو؛ يلزم اختبار حي اختياري بعد إعداد الحسابات والنموذج.
