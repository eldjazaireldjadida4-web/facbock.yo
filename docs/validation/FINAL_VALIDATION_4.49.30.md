# التحقق النهائي — الإصدار 4.49.30

## الخلاصة

ميزة جديدة: تحديث تلقائي للتطبيق من GitHub Releases. وحدة `updater.py`
جديدة تفحص أحدث إصدار غير تجريبي، وزر «التحديثات» في رأس الواجهة
لفحص يدوي، وفحص تلقائي عند البدء مرة في اليوم كحد أقصى مع خيار
`SETTINGS.CHECK_FOR_UPDATES` لإغلاقه. عند وجود إصدار أحدث تظهر نافذة
بملاحظات الإصدار؛ في النسخة المجمّدة على Windows ينزّل المثبّت بعد
التحقق من حجمه وبصمة PE ثم يشغّله ويغلق التطبيق، وفي نسخة المصدر
يفتح صفحة الإصدار في المتصفح.

## التصميم

- قناة التحديث: `api.github.com/repos/eldjazaireldjadida4-web/facbock.yo/releases/latest`
  (مستودع عام، بلا مصادقة)؛ أصل المثبّت هو المنتهي بـ
  `-windows-x86_64-setup.exe` والمطابق لرقم الإصدار المعلن.
- الفحص لا يرفع أبداً: أي فشل شبكي أو تحليلي يعيد None بهدوء ويسجّل
  نوع الخطأ فقط؛ الخيط الخلفي لا يلمس Tkinter إطلاقاً — النتائج تمر
  عبر `_uiq` إلى `_handle_ui_event` في الخيط الرئيسي.
- التنزيل والتثبيت لا يحدثان إلا بنقرة صريحة: الفحص التلقائي لا
  ينزّل شيئاً، وزر «تحميل وتثبيت» ينزّل أولاً ثم يسأل قبل التثبيت.
- التحقق من التنزيل: الحجم المعلن في الإصدار + أول بايتين `MZ`
  (بصمة PE)؛ أي عدم تطابق يحذف الملف الجزئي ويرفع UpdateError.
- الخنق: آخر فحص محفوظ في `state.json` (`last_update_check`)؛
  الفحص التلقائي يتخطى ما لم تمر 24 ساعة، واليدوي يتجاوز الخنق.

## الاختبارات

- 28 اختباراً جديداً في `tests/test_updater.py` (شبكة مزيفة بالكامل):
  تحليل الإصدارات (`v4.49.30`، صيغ تالفة)، مقارنة رقمية مع تمديد
  الأقصر، فحص أحدث/مساوٍ/أقدم، فشل شبكي بلا رفع مع `on_error`،
  حمولات JSON تالفة أو بلا أصل مثبّت، تنزيل صحيح مع تقدّم، رفض
  عدم تطابق الحجم وملف غير PE مع حذف الجزئي، رفض رابط غير https،
  حد مرة في اليوم (بما فيه طابع مستقبلي وتالف)، `is_frozen`،
  تشغيل المثبّت، وربط الواجهة (`UI_KEYS` + طرق `App`).
- اختبار `test_version_exits_0_under_strict_cp1252` صار يقارن
  `version.APP_VERSION` بدل رقم مثبّت، حتى لا يفشل عند كل رفع إصدار.
